# RAG - Streamlit Demonstration Prompts

## Overview
This document contains demonstration prompts (questions) for showcasing the FANalyze RAG system capabilities. Each prompt is designed to demonstrate a specific data source and includes verification SQL queries to validate the RAG response against Snowflake.

**Optimization for Speed**: All prompts are optimized to return results in **10 seconds or less** by:
- Limiting result sets to 1-5 records (instead of 50)
- Using simpler queries with fewer joins
- Removing time-based filters that require scanning large date ranges
- Focusing on specific, targeted questions

**Data Sources:**
1. **Batch Data**: Historical and future concert data from CSV files (`fact_shows` table)
2. **Streaming Data**: Real-time ticket sales events (`fact_ticket_sales` table)
3. **Pinecone/PDF**: Document-based knowledge (musician biographies, ticket sales strategies)
4. **Synthesis**: Combined queries using cached data from multiple sources

## 1. Batch Data Demonstrations

### Prompt 1.1: Historical Show Details (Past Concerts)
**Question:**
```
Show me the 3 most recent past concerts for [ARTIST_NAME].
```

**Example:**
```
Show me the 3 most recent past concerts for Taylor Swift.
```

**Verification SQL Query:**
```sql
SELECT 
    COALESCE(da.artist_name, 'Unknown') as artist_name,
    fs.show_date,
    COALESCE(dv.venue_name, 'Unknown') as venue_name,
    fs.city_name,
    fs.state_code,
    fs.tickets_sold,
    fs.revenue
FROM FAN_MARTS.fact_shows fs
LEFT JOIN FAN_MARTS.dim_artists da ON fs.artist_id = da.artist_id
LEFT JOIN FAN_MARTS.dim_venues dv ON fs.venue_id = dv.venue_id
WHERE LOWER(da.artist_name) LIKE LOWER('%Taylor Swift%')
    AND fs.show_status = 'Historical'
ORDER BY fs.show_date DESC
LIMIT 3;
```

**Expected Response Elements:**
- Artist name
- Show dates (past dates)
- Venue names
- Tickets sold (historical data)
- Revenue (historical data)
- City and state locations

**What to Verify:**
- All dates should be in the past
- `show_status` should be 'Historical'
- Revenue and tickets_sold should match the RAG response

## Demonstration Flow Recommendations

### Recommended Order for Presentation:

1. **Start with Batch Data** (Prompt 1.1 or 1.2)
   - Shows historical or future concert data
   - **Fast**: Returns 3 results in <5 seconds
   - Easy to verify with simple SQL query
   - Demonstrates structured data querying

2. **Move to Streaming Data** (Prompt 2.1 or 2.2)
   - Shows real-time ticket sales
   - **Fast**: Returns 3-5 results in <5 seconds
   - Demonstrates freshness of data
   - Highlights streaming pipeline capability

3. **Demonstrate PDF/RAG** (Prompt 3.1 or 3.2)
   - Shows document retrieval
   - **Fast**: Simple questions return in <3 seconds
   - Fake information proves PDF source
   - Demonstrates semantic search capability

4. **End with Synthesis** (Prompt 4.4)
   - Combines all three sources
   - **Fast**: Returns 1 result per source in <10 seconds total
   - Shows agent's ability to synthesize
   - Demonstrates full RAG system capability

### Key Points to Highlight:

- **Data Source Identification**: Agent should clearly indicate which tool/data source it's using
- **Verification**: Each response can be verified by running the provided SQL queries
- **Synthesis**: Agent combines multiple sources intelligently
- **Context Awareness**: Agent maintains context across multiple queries in synthesis prompts

## Notes for Presenter

1. **Before Demo**: 
   - Ensure Snowflake tables are populated with recent data
   - Verify Pinecone index contains processed PDF documents
   - Test a few queries to ensure they return results

2. **During Demo**:
   - Run the verification SQL queries in Snowflake after each RAG response
   - Show that the data matches between RAG response and SQL results
   - Highlight the data source (batch/streaming/PDF) for each response

3. **Verification Tips**:
   - Use Snowflake's query history to show the exact queries executed
   - Compare RAG response numbers with SQL query results
   - For PDF responses, point out the fake information as proof of document source

4. **Troubleshooting**:
   - If a query returns no results, check if data exists in Snowflake
   - If PDF responses don't appear, verify Pinecone index is populated
   - If synthesis fails, check agent logs for tool call sequence
